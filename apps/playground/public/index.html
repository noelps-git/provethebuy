How it works

From checkout to evidence
in three steps.

Step 01

The AI agent signs the request

The shopping agent attaches an HTTP Signature and a mandate to every checkout call — binding the order to the shopper's explicit authorisation.

Step 02

ProveTheBuy verifies it instantly

The verifier checks the Ed25519 or ECDSA P-256 HTTP Signature (NIST FIPS 186-5) against the live directory key, validates the SHA-256 nonce (FIPS 180-4), confirms the mandate, and applies your policy — in under 5 ms.

Step 03

Dispute? Evidence is already built.

Every verification record, key snapshot, and order hash is written to a tamper-evident ledger. When a chargeback arrives, the complete evidence pack is one click from submitted.

Cryptographic foundations
NIST FIPS 186-5
Digital Signature Standard
Covers Ed25519 (EdDSA), ECDSA P-256, and RSA-PSS — the three signature schemes used by Visa TAP, Mastercard Agent Pay, and Web Bot Auth. FIPS 186-5 (2023) was the first federal standard to include EdDSA.
Ed25519ECDSA P-256RSA-PSS
NIST FIPS 180-4
Secure Hash Standard (SHA-2)
SHA-256 is used for nonce hashing, JWK public-key snapshots, order canonicalisation (RFC 8785), SD-JWT disclosure digests, and every link in the tamper-evident evidence ledger chain.
SHA-256RFC 8785 JCSSD-JWT
NIST SP 800-186
Elliptic Curve Domain Parameters
P-256 (secp256r1) is the approved NIST curve used by ECDSA agent keys and JWKS directory entries. Provides 128-bit equivalent security strength — the threshold for signatures through the 2030s per SP 800-131A.
P-256128-bit securitySP 800-131A
RFC 9421
HTTP Message Signatures
The IETF standard that defines how to sign HTTP requests end-to-end. ProveTheBuy verifies the signature base string covering method, authority, path, headers, and the nonce — making every covered component tamper-evident.

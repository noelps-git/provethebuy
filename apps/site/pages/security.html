Security

ProveTheBuy sits next to your checkout, so it's built to never put a sale at risk and never hold card data.

Your checkout comes first

{{icon:check}} Fail-open by default

The verifier runs in your own server. It fails open by default: if it errors, the order goes through and the error is recorded.

{{icon:check}} Background sync with bounded queue

The Cloud connection sends records in the background with a short timeout and a bounded queue, so if we're slow or down, orders still go through and records are sent later.

No card data

We add nothing to your PCI scope.

{{icon:lock}} Agent signatures only

We read agent signatures, signed mandates and payment token limits. We never decrypt payment containers or see card numbers, so we add nothing to your PCI scope.

Cryptography

Standard, NIST-approved algorithms throughout.

{{icon:lock}} Signature verification

Signatures use Ed25519, ECDSA P-256 and RSA-PSS through Node's crypto module.

{{icon:lock}} Record hashing

Records are hashed with SHA-256 over RFC 8785 canonical JSON.

{{icon:check}} Not a FIPS module

These are standard, NIST-approved algorithms; ProveTheBuy is not itself a FIPS-validated module.

Isolation and access in Cloud

Every layer is locked down by default.

Data isolation

  • {{icon:lock}} Every workspace's data is separated by Postgres row-level security under a restricted database role
  • {{icon:lock}} API keys are shown once and stored only as SHA-256 hashes

Authentication and audit

  • {{icon:check}} Sign-in is through GitHub or Google; we store no passwords
  • {{icon:check}} Team members get roles, and every sensitive action is written to an audit log

Evidence you can check

Every record is independently verifiable and tamper-evident.

{{icon:check}} Hash-chained records

Each record carries a SHA-256 hash and links to the one before it. Every record's hash is checked when it arrives and anything edited is rejected.

{{icon:check}} Retention with integrity

When a record's retention ends we delete its contents but keep its hash, so the chain still verifies.

{{icon:lock}} Signed confirmations

Shopper confirmations are signed with our Ed25519 key, published at https://app.provethebuy.com/.well-known/jwks.json.

Stripe and billing

Minimal permissions, no money movement.

{{icon:check}} Limited Stripe Connect access

Stripe access uses Connect and is limited to reading disputes and submitting evidence you approve or rules you set. We never accept a dispute for you and never move money.

{{icon:check}} Billing via Dodo Payments

Billing is handled by Dodo Payments.

Reporting a vulnerability

Email security@provethebuy.com. We acknowledge within 2 working days. The threat model is in the docs.

Detection

Seven signals no single request gives away

Every signal below can be read from what reaches your server, or from headers your CDN already adds. No client-side code required.

Hidden routes hit first

Requests to API routes that no served page links to, before any page that would load them. The agent finds routes by reading JavaScript bundles; people find them by clicking.

Auth surface sweep

Sign-up, login, password-reset and OTP endpoints hit in a short burst. Expired, reused or malformed tokens. One session touching many accounts.

API then browser

A run of failed direct API calls (401, 403, 429) followed minutes later by a full browser session on the same account, cookie or network. The fallback to a browser is what makes these frameworks work.

Recon footprint

robots.txt, sitemap, .well-known paths, OpenAPI or GraphQL introspection, error-driven guessing of IDs and paths. Mapping the app has to happen before attacking it.

Model-loop timing

Regular pauses of a few seconds between steps (the model thinking), then bursts. No idle reading time. Changing it slows the attack down.

Claim vs proof

A User-Agent naming a known agent but no cryptographic signature. Or a valid signature whose key then behaves outside its policy. Signatures can't be forged, so the claim is checkable.

Network context

TLS fingerprint (JA4), ASN and residential-proxy flags passed in by the CDN, if you have them. Supporting evidence only — easy to buy, never decisive alone.

Prove what the agent was allowed to buy.

An open-source verifier for orders placed by AI agents. It checks the agent's signature and the shopper's signed limits at your checkout, and keeps a record you can still verify when the chargeback lands months later.

Three checks at order time. One record for dispute time.

It runs inside your own server, never sees a card number, and starts in shadow mode, so it records what it would decide without blocking a sale.

  1. Verify the agent

    Checks the HTTP message signature (RFC 9421, Web Bot Auth) against the card network's key directory, and rejects replays, expired signatures and edited requests.

    keyid, nonce, created, expires

  2. Bind the order

    Checks the shopper's signed mandate (Verifiable Intent, AP2) and payment token limits, and confirms this exact cart, amount and merchant are inside them.

    RFC 8785 + SHA-256 order hash

  3. Keep the proof

    Writes a hash-chained evidence record with a snapshot of the key. When a dispute arrives, it re-verifies and builds the evidence pack.

    evidence.jsonl

What it verifies today

Agent-commerce standards are still settling. This says plainly how far each one is implemented, and where we follow an assumption rather than a published rule.

StandardWhat is checkedStatus
RFC 9421 HTTP Message SignaturesEd25519, RSA-PSS-SHA512, ECDSA P-256. Passes the RFC's own Ed25519 test vector (B.2.6).STABLE
Web Bot Authagent-browser-auth and agent-payer-auth tags, key directories, nonce replay.STABLE
Visa Trusted Agent ProtocolSignature against the Visa JWKS; consumer-recognition and payment-container body objects.BETA
Mastercard Agent Pay / Verifiable Intent3-layer SD-JWT chain (issuer, user, agent); amount, merchant and item constraints.PREVIEW
AP2 (Agent Payments Protocol)Cart mandate with merchant and user signatures; intent mandate with an unattended-amount threshold.PREVIEW
Stripe shared payment tokens / ACPAllowance limits: amount, currency, merchant, expiry.LIMITS ONLY

Details for each standard are in Protocols. Test vectors for other-language ports are in the repo.

Questions developers ask

Something missing? Open an issue.

Will it block real customers?

Not unless you tell it to. It starts in shadow mode and only records decisions. Requests without an agent signature come back as not_agent and pass straight through. If the verifier itself errors, the order goes through by default.

Does it touch card data?

No. It reads agent signatures, signed mandates and payment token limits. It never decrypts payment containers or sees card numbers, so it adds nothing to your PCI scope.

Which runtimes and frameworks work?

Node 18.17 and newer, with Express middleware included. The core takes a plain request object, so other frameworks need a few lines. Python and Go verifiers are planned and will pass the same test vectors.

How does a dispute months later still verify?

Each record keeps the raw signed request and a snapshot of the key used that day, chained by hash. Re-verification uses that snapshot, so it works even after the agent rotates its key.

What does it cost?

The verifier and CLI are free and Apache-2.0. Cloud has a free plan for up to 1,000 verified orders a month, and paid plans from $9 a month for dispute handling. See pricing.

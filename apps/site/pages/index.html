How it works

      
Three checks at order time. One record for dispute time.

      
Runs inside your server, never sees a card number, starts in shadow mode.

FAQ

      
Questions developers ask

      
Something missing? Open an issue.

    

    

      
Will it block real customers?+
Not unless you tell it to. Starts in shadow mode — only records. Requests without an agent signature pass through. If the verifier errors, the order goes through by default.

      
Does it touch card data?+
No. It reads agent signatures, signed mandates and payment token limits. Never decrypts payment containers or sees card numbers. Adds nothing to PCI scope.

      
Which runtimes work?+
Node 18.17+ with Express middleware. The core takes a plain request object. Python and Go ports are planned and will pass the same test vectors.

      
How does a dispute months later still verify?+
Each record keeps the raw signed request and a snapshot of the key used that day, chained by hash. Re-verification uses that snapshot, so it works even after the agent rotates its key.

      
What does it cost?+
The verifier and CLI are free and Apache-2.0. Cloud: free up to 1,000 verified orders/mo, paid plans from $9/mo for dispute handling.
